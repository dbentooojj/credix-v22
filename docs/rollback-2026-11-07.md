## Publicar

No GitHub, abrir **Actions > Publicar em producao > Run workflow**, selecionar
`main` e preencher a confirmacao `PRODUCAO`. O workflow atual cria backup do banco
antes da troca dos containers e tenta retornar a aplicacao anterior se a
publicacao falhar. Esse backup sera criado no deploy; a copia Git acima contem
codigo, sem dados nem segredos de producao.

## Retornar a aplicacao anterior depois de um deploy concluido

Como esta entrega nao altera o schema, o retorno pode usar as duas imagens
anteriores sem restaurar o banco. Executar na VPS somente se for necessario
retornar, e antes de qualquer outra entrega com novas migrations:

```bash
set -e
cd /opt/credix
test -s .deploy.env
cp -p .deploy.env ".deploy.env.before-rollback-$(date -u +%Y%m%dT%H%M%SZ)"
grep -q '^IMAGE_TAG=' .deploy.env
sed 's/^IMAGE_TAG=.*/IMAGE_TAG=6c3e18503059a5ba867b9ff42a6f30e7b0599259/' .deploy.env > .deploy.env.rollback
chmod 600 .deploy.env.rollback
docker compose --env-file .env --env-file .deploy.env.rollback pull backend frontend
mv .deploy.env.rollback .deploy.env
docker compose --env-file .env --env-file .deploy.env up -d --no-deps --force-recreate backend frontend
docker compose --env-file .env --env-file .deploy.env ps
docker exec credix_backend sh -c 'wget -qO- "http://localhost:${PORT:-4000}/health"'
docker exec credix_frontend wget -qO- http://localhost:3000/login >/dev/null
```

Conferir login, carteira, clientes, parcelas e recebimentos. O retorno das imagens
preserva os registros feitos apos o deploy. Os backups PostgreSQL ficam em
`/opt/credix/backups`; sua restauracao e uma operacao separada, que pode descartar
registros mais novos e nao faz parte deste retorno da aplicacao.

Se for necessario alinhar a main ao codigo anterior, reverter o commit desta
entrega com `git revert`, publicar a reversao e rodar novamente o workflow. A tag
preservada permite comparar o codigo sem reescrever o historico da main.
